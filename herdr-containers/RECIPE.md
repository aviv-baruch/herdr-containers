# Herdr Containers

A familiar Herdr workspace gains a Containers list between Spaces and Agents. Running dev containers open as spaces, saved connections remain visible when Docker is unavailable, and the footer Settings screen lets you choose which containers appear.

![Herdr Containers](preview.png)

## What you see

The main layout has a 268 px chrome colored sidebar beside the canvas colored workspace, with a 1 px theme border between them. From top to bottom, the sidebar has Herdr's 46 px brand, a Spaces block, a Containers block, an Agents block, and a 69 px footer. Spaces and Agents each have a 90 px minimum; Containers has a 35 px minimum. The three list blocks each start with equal weight and share the available height. The brand and work area keep the shipped main layout's tabs, panes, panel, and status bar.

Containers has a 31 px heading with 11.5 px type and a chevron. Its scrollable list uses the sidebar's chrome surface and theme border. The **Dev containers**, **Other containers**, and **Gone** groups appear when they contain rows; each header is 30 px high with 11 px `dim` `font_medium` type and a `dim` count. Rows are 30 px high with 13 px type, 11.5 px `dim` details, and theme colored status dots. A dev row shows a folder icon, name, local folder, and connection or state. An other row shows a server icon, name, image, and state. A saved machine whose container has disappeared appears in Gone with **Forget**. While Docker is unavailable, that last group says **Saved machines** and its rows say **Disconnected**. A narrow sidebar becomes an icon rail below 160 px.

Agents keeps its normal priority or space groups and adds **Disconnected** at the end when agents belong to a disconnected container machine. The footer shows **Settings** and **Add machine**; its Settings dialog has a **Containers** section with **Show other containers** and **Show stopped dev containers** switches.

## How it behaves

Agent statuses keep the shipped Agents look: a working agent has a spinning `working` colored glyph, a blocked agent a `blocked` colored **Needs you** pill (a **!** under the Needs you heading), a done agent a filled 7 px `done` colored dot, and an idle agent a 7 px `idle` colored ring. An agent whose container machine is disconnected loses its status: it moves to **Disconnected**, its name, icon and subagents turn `dim`, and it says **disconnected**.

Click a running dev container to connect it and open or select a space in its workspace folder. A running plain container first asks for **Connect** or **Cancel** inline and explains that connecting copies Herdr Core into it. Clicking that row again closes the question. A paused row says **Paused** and asks you to unpause it before opening. A stopped dev container offers **Start**. An unreachable saved connection can offer **Repair**, which first makes a spare connection, then replaces the old one. Connection, start, repair, disconnect, and forget actions show immediate progress or an error.

Click the **×** on a saved row, then **Disconnect** to close its spaces and remove its machine connection while leaving the container running. The Spaces machine group disappears immediately; a removal error restores the row. **Forget** closes spaces and removes a saved machine whose container is gone. If Docker is down, the list shows “Docker isn't running,” saved container machines say **Disconnected**, Spaces dims their rows and machine groups, and Agents moves their agents into Disconnected.

Click the Containers heading or press **Ctrl+Shift+Y** to fold the block to its 35 px heading; click again to expand it. The three group headings fold their own rows and retain counts. Container rows highlight on hover like Spaces rows; Containers group headings do not take a hover background. The list refreshes every 5 seconds while open and the window is active. The two footer Settings switches change which plain containers and stopped dev containers appear and persist across restarts. Palette and keyboard Settings still open Herdr's original settings screen.

## Built from

- `layouts/main-containers.json` clones Herdr app 0.1.9 `main`: `root` is a row with `sidebar` and `work`. The `sidebar` column holds shipped `workspace-chrome` for `brand`, then `sidebar-lists` with `spaces` (`spaces-containers`), `containers` (`containers`), and `agents` (`agents-containers`), then `sidebar-footer` (`workspace-chrome-containers`, `props: { "footer": true }`). The work tree retains shipped `tabs`, `pane`, `files`, `changes`, and `workspace-status` mods. The layout key `ctrl-shift-y` sends `containers.toggle` only in `layout:main-containers`.
- `mods/containers` calls Herdr `exec`, `hc`, `machines`, `spaces`, `run`, `theme`, `layout`, `shared`, `setShared`, `nextCommand`, and `window`. It runs `hc-devcontainer ls --all --json`, `exists VIA`, and `start ID` through `exec`; it calls `hc machine ls --json`, `add --name NAME --via VIA --install --json`, `rm NAME`, and `rename OLD NEW`. It uses `run` for `space.new`, `space.select`, `space.close`, and `layout.resize`. `shared` / `setShared` hold visibility, folded groups, removing names, and disconnected machines. `nextCommand` receives the toggle key action.
- `mods/spaces-containers` clones shipped Spaces and uses `shared("containers.removing")` and `shared("containers.down")` to hide removing machine groups and dim disconnected ones. It refreshes a machine list through `hc`, runs `git` through `exec` in space folders, watches repository folders with `watchFolder`, and uses `run` for space actions plus `openOverlay` for the shipped space menu.
- `mods/agents-containers` clones shipped Agents and maps each agent's space to its machine. It moves disconnected agents to their own group, dims their names and subagents, and opens its own sorting popup with `openOverlay`. It uses Herdr `agents`, `spaces`, `terminals`, `panes`, `run`, `shared`, and `setShared` for its usual controls.
- `mods/settings-containers` clones Herdr's shipped frame Settings. The footer opens it with `openOverlay({ mod: "settings-containers", kind: "dialog", width: 880, props: { section: null } })`. Its Containers switches use `shared` / `setShared`; the rest of the shipped screen uses `hc`, `run`, `readTextFile`, `writeTextFile`, and `appHome` for machine controls and settings. `mods/workspace-chrome-containers` clones shipped chrome, uses `props().footer` to select footer or brand rendering, and changes the footer Settings action to that overlay. Its other actions use `run` and `layout.resize`.
- The container and clone art consists of SVGs in the mods and the shipped Herdr icon paths listed below. The space avatar colors are `#22a99a`, `#e3814f`, `#5b8def`, `#8b7cf6`, `#3fae6a`, and `#d9649a`.

## Watch out

**Requirements:** Put the repository's `requirements/hc-devcontainer` on the PATH seen by both Herdr app and core, for example in `~/.local/bin`, and provide Docker or a Docker compatible Podman binary on that host. `HC_DEVCONTAINER_DOCKER=podman` selects Podman. The optional `requirements/feature/herdr-core` downloads Herdr Core from releases.herdr.dev when the image builds and persists the core binary and identity across rebuilds. Connecting or repairing a container runs `hc machine add … --install`. A container without a compatible Herdr Core (plain containers, and dev containers without the Feature) gets one at `~/.local/bin/herdr-core` of the user Herdr connects as, plus an `hc` link if it has none, and that core is restarted. hc copies its own binary when the container's OS and CPU match the host's; otherwise, as on any macOS host, it first downloads the matching build of its version from releases.herdr.dev. A container without `sh` (distroless) cannot connect this way. If the core cannot find `hc-devcontainer`, its shell exits 127 and `hc machine add` may report “hc is not installed.” Restart a core whose PATH was changed after it started.

These mods **run programs and read files outside their own folders**. `containers` runs `hc-devcontainer` and `hc`; the helper runs `docker` or `podman` and inspects host containers, labels, mounts, and workspaces. `spaces-containers` runs `git` in space folders, watches repository folders, and calls `hc`. `settings-containers` reads layout JSON files and reads and writes the app home's `settings.json`; it also calls `hc`. The other clones call Herdr commands and use the app's shared state. No package mod makes its own network request; the network use is the hc and Feature downloads described above, and the core and app update controls inherited by the cloned Settings screen keep their shipped behavior.

All paths to a clone's own SVGs resolve inside this package. The remaining **shipped asset cross references** are: `containers` uses `mods/workspace-chrome/{folder,server,x,chevron-right,chevron-down}.svg`; `spaces-containers` uses `mods/workspace-chrome/{server,monitor,chevron-right,chevron-down,plus,branch}.svg`; `agents-containers` uses `mods/workspace-chrome/{clock,layers,check,spinner,chevron-right,chevron-down,pin,pin-off}.svg`; `settings-containers` uses `mods/workspace-chrome/spinner.svg`; and `workspace-chrome-containers` uses `frame/welcome/herdr.png`. Agents also draws icons named by Herdr's installed program table. Those shipped assets and its `menu`, `picker`, and `machine-add` mods must exist in the app home.

The four clones are based on Herdr 0.1.9. On a newer Herdr, rebuild from this recipe or run `tools/build-package.py` against that version's defaults, then check every clone. Shipped Spaces caches `hc machine ls` for 15 seconds; its clone refreshes on removal or connectivity changes so groups change promptly. The footer's Settings action opens the cloned Settings screen; palette and keyboard Settings open the original screen without the Containers section. The connector chooses the closest matching bind mount for a dev container's workspace, falling back to its working directory; an empty directory or `/` leaves the space folder unset. Remote terminals then use that user's `HOME` if available, or the core's current directory. A container's `remoteEnv` and `userEnvProbe` do not affect the plain `docker exec` connection. A folder shared by multiple running dev containers selects the newest and warns on stderr.

## Done when

- `herdr-app check` passes for all five package mods: `containers`, `spaces-containers`, `agents-containers`, `settings-containers`, and `workspace-chrome-containers`.
- `hc-devcontainer ls --all --json` lists running and paused containers and stopped dev containers, and Containers shows the corresponding Dev and Other groups.
- Clicking a running dev container opens or selects a space in its workspace folder; clicking a plain container shows the inline confirmation before connecting.
- Disconnecting a saved row removes its Spaces group immediately, then removes the machine connection; Docker going down shows **Disconnected** in Containers, Spaces, and Agents.
- Footer **Settings → Containers** toggles change the list; **Ctrl+Shift+Y** folds and unfolds Containers.
